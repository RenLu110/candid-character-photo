# 测试方法

用候选 Skill 的本地副本做测试；测试代理只拿到 Skill、原始请求和必要参考，不带作者聊天历史。至少两组人物，一组真人参考、一组原创人物，另加一个明确成年角色入口。

## 图片观察

1. 真人参考三张：同人物、同服装、三场景，检查面部和衣服一致性。
2. 原创人物三张：不同于真人参考的性别和造型，其中一张手机随手拍，检查人物连续性与成像差别。
3. 角色名一张：检查成年角色识别特征与日常动作。
4. 每张记录实际提示词、工具完成结果、源输出与最终文件、问题和重试。将中断、失败和修正计入记录，不只保留最好看的结果。
5. 对实际图像检查人物、指定内容、动作、观察位置、可读性、物理逻辑、组图差异。照片不能仅凭提示词获得通过。

首轮参考门槛：7张中至少6张可用，最终图片无明显换人、严重人体错误或漏图。此阈值仅用于发布候选验收；“可用但有保留”必须写明保留项，不等于无瑕疵或统计成功率。

rc2增加距离感验收：远景中人物应较小、环境主导；按头至脚（坐姿按坐姿外接高度）占画幅约20%–35%观察，不把全身入画等同于远景。默认3张须含远／中远／中景，默认5张以上至少三分之一远景；用户指定单一景别时遵循用户。检查近处障碍物、中间空间和远处人物的层次，远景不要求近景式五官精度。

## 行为场景

- 仅要提示词，不得调用生图。
- 参考是不同人物，询问主体，不能混脸。
- 无生图工具，明确无法出图，不能声称完成或擅自换付费服务。
- 批量部分失败，保留成功图片，只补失败图，遵守重试上限。
- 新会话丢失人物参考，不能假装记得人脸。
- 陌生角色且年龄不明，不能编造身份特征。

这些场景可用独立代理响应演练，必须标明“行为模拟”，不能伪称实际服务故障注入。

## 发布前

- 检查 YAML、所有本地链接、UTF-8 编码、未完成占位符、私有绝对路径、意外原始照片或秘密。
- 将 ZIP 解压到新目录，核对清单和 SHA-256，复制其中 Skill 至隔离技能目录。
- 使用隔离副本完成一次新的最小请求，检查运行时能找到所有引用文件。
- 保留源码包、测试报告、发布清单。GitHub 创建／上传在获得用户最终确认之后进行。
